## Implementation notes

- The `HEXCHR$` runtime routine is named `BAS_SHEX`, not `BAS_SHEXCHR` as written above.
- Tabs: hubasic2sl reads a tab in the program text as a space, also inside string literals (`Text/HuSource.cs`: `b == '\t' ? ' '`, `ToX1('\t')` is `' '`). So a tab typed between the groups of a `HEXCHR$` literal works as a separator. Only a tab made at run time (`CHR$(9)`) is error 5. Checked in X1Pen: `HEXCHR$("01<tab>02")` has 2 bytes; `HEXCHR$("01"+CHR$(9)+"02")` and `HEXCHR$("01,02")` stop with `Illegal function call in 30`. The entry says this and cites `HuSource.cs`; the E2E test covers both cases.
- Checked in X1Pen beyond the plan: `C$=A$:B$=MIRROR$(C$)` leaves A$; `N%(ASC(S$))=ASC(MIRROR$(S$))` stores into `N%(1)`. Both are in the entry and the E2E test.
- docs/X1PEN.md names no bundle revision and no HEXCHR$ rule, so it is unchanged. `docs/X1PEN_MCP.md` already says the reference is reviewed whenever the bundle is replaced.
- Mutation checks done:
  - Putting "an odd length is error 5" back into the reference fails the new reference test.
  - Serving the 5abbffa bundle from `dist/` fails the new E2E test (`MUSIC` is HB0301 there).
- Before writing the reference: with only the bundle imported, only the stamp test failed (reference 48/1), and the toolchain fixtures passed. The 4 testdata binaries are identical; only `expected.json`'s revision changed.
