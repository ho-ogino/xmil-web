# PCG タブに「使い方」: FuzzyBASIC・SLANG で PCG を定義するお手本（コピーのボタン付き）

## Purpose

PCG タブ（DEFCHR TOOL for Web）から「X1Pen に挿入」すると、HuBASIC には `DEFCHR$` の行がそのまま入る（見れば分かる）。FuzzyBASIC と SLANG に入るのは**データだけ**（ASM タブの `DB`、SLANG の `ARRAY BYTE`）で、それを**どう使って PCG にするか**（`PCGDEF` の呼び方・番地の決め方・表示のしかた）が画面のどこにも無い。

ひろしさんの決めごと（2026-10-30、Secretary 経由）: **案 A**。PCG タブの上の並び（BASIC タブの「Manual」、HuBASIC の「Options」と同じ所）に「使い方」を置き、押すと小さな枠に **FuzzyBASIC と SLANG のお手本（コピーのボタン付き）**。お手本は**実際に X1Pen で動くことを必ず確かめる**。docs（`docs/X1PEN.md`）にも同じ中身を 1 か所だけ置いてよい。

**やらないこと**: 入れる文へのコメントの追加（案 B）、MCP のリファレンスへの追加（`fuzzybasic.x1.pcg-definition`・`slang.x1.pcg-definition` に同じ形のお手本がもうある。AI 向け）、HuBASIC のお手本、版上げ、本番への反映、DEFCHR TOOL（上流）の変更。

この PR は PR #153（PCG タブ 2 本目、マージ待ち）の上に積む（base は #153 のブランチ）。

## Observed evidence

- 上の並び（`html/x1pen.html` の `#editor-tabs`）: タブのボタンのあとに `.editor-tab-action`（`margin-left: auto`）のボタン・リンクが並ぶ。ASM の「Import」、SLANG の「Import」、BASIC の「Manual」（外部リンク）、HuBASIC の「Options」は `hidden` クラスで、`setActiveEditorTab(target)`（`html/x1pen.js`）がタブに合わせて出し入れする。「Charmap」はいつも出ている。
- HuBASIC の「Options」の枠（`#hubasic-options-panel`）: `#editor-tabs` の下に `position: absolute; top: 30px; right: 8px; z-index: 60; width: 320px; max-height: calc(100% - 40px); overflow-y: auto` の枠。開閉は `openHuBasicOptionsPanel()`／`closeHuBasicOptionsPanel(restoreFocus)`: ボタン（`aria-expanded`）で開け閉め、「閉じる」、枠の中の Esc、枠とボタンの外の `pointerdown`（capture）、HuBASIC 以外のタブへの切り替え（`setActiveEditorTab` の中）、エディタの iframe にフォーカスが入ったとき（iframe の中のクリックはこのページの `pointerdown` に届かないため、iframe の focus で閉じる）。試験は `tests/x1pen_automation_test.mjs` の「Options」の試験（開く・Esc・外のクリック・フォーカスの戻り先）。
- PCG タブの iframe のフォーカスは `X1PenDefchrToolBridge.focus`（`defchrtool/x1pen-host.js` が window の focus で呼ぶ）で X1Pen に届く。
- PCG タブのボタンの `title` が「…insert them into the ASM or SLANG tab」のまま（PR #153 で HuBASIC にも入るようになった）。
- **お手本を X1Pen で動かした結果**（scratch の Playwright。確認用サーバーの PR #153 のビルド。`X1PenAutomation.setProgram` → `run` → `debugger.readVram` で文字と属性 → `captureScreen` でマスの色）:
  - データ: $41 は B の面だけ全部 1（青）、$42 は R の面だけ全部 1（赤）。行ごとに B,R,G（ASM(x3)／BIN(x3) の並び）。
  - **FuzzyBASIC**: ASM タブ `\tORG\t$B000` + `; CHR $41`／`\tDB\t…` ×2、BASIC タブ `10 LIMIT $AFFF` / `20 BLOAD "PROGRAM.BIN",$B000` / `30 PCGDEF 65,$B000` / `40 PCGDEF 66,$B018` / `50 WIDTH 40:TCOLOR $27` / `60 PRINT CHR$(65);CHR$(66)` / `70 TCOLOR 7`。→ RUN の結果 `ASM: 48 bytes (B000h-B02Fh)`、画面の左上 2 マスが文字 65・66、属性 $27・$27、色は青一色（0,0,248）・赤一色（248,0,0）。
  - **SLANG**: `ARRAY BYTE PCG41[] = { … // $41, … // $42 };` + `MAIN()` で `WIDTH(40);` `PCGDEFS($41, PCG41, 2);` `LOCATE(0, 0);` `TATTR($27); PRINT(CHR$($41));` `TATTR($27); PRINT(CHR$($42), /);` → 左上 2 マスが 65・66、属性 $27・$27、青一色・赤一色。
  - SLANG の `TATTR` は**カーソルのマス 1 つ**の属性を決める（リファレンスの notes「Set attribute bit 5 on the target text cell with TATTR before printing」）。最初に Secretary に出した案（`TATTR($27);` 1 回で 2 文字）では 2 文字目が属性 7 になり、ROM の文字が出た。→ 1 文字ごとに `TATTR($27);` を置く。
  - FuzzyBASIC の `TCOLOR` は、そのあと PRINT する文字すべてに効く（2 文字とも $27）。
- MCP のリファレンス（`mcp/reference/fuzzybasic.json`・`slang.json`）の PCG の項のお手本と同じ流れ（LIMIT → BLOAD → PCGDEF → TCOLOR → PRINT、PCGDEFS → TATTR → PRINT）。リファレンスは変えない。

## Change scope

1. `html/x1pen_pcg_howto.js`（新、`window.X1PenPcgHowto`）: お手本の中身（**1 か所**）。`examples: [{ id, title, note, blocks: [{ label, code }] }]`。

## Edge cases and test plan

### Node（`tests/defchrtool_test.mjs` に足す）

- `X1PenPcgHowto.examples` が FuzzyBASIC・SLANG の 2 つで、ブロックのラベルが「ASM タブ」「BASIC タブ」「SLANG タブ」。
- **docs と同じ**: `docs/X1PEN.md` の「PCG の定義のお手本」の節のコードブロックが、各ブロックの `code` と 1 字違わず同じ（どちらかだけ直すと落ちる）。
- **組み立てて通る**: FuzzyBASIC の ASM ブロック + `X1PenPcgExport.build` で作った DB（$41・$42、ASM(x3)）を `X1PenZ80Asm.assemble` → エラーなし、$B000 から 48 バイト、`PCGDEF 66,$B018` の番地が 2 文字目の頭（$B000 + 24）。SLANG のブロックのコメント行の所に `build` で作った配列（BIN(x3)）を入れて `X1PenSlangCompiler.compile` → エラーなし、配列名が `PCG41`（`PCGDEFS($41, PCG41, 2)` と合う）。
- BASIC ブロックの `PCGDEF` の番地と文字コードが、説明（$41・$42、24 バイトずつ）と合う。

### Chrome（`tests/x1pen_automation_test.mjs` に足す）

- 「使い方」は PCG タブのときだけ出る（BASIC・ASM・SLANG・HuBASIC では隠れる）。
- 開く → 枠に FuzzyBASIC・SLANG の見出しと 3 つのコード（中身は `X1PenPcgHowto` と同じ）、`aria-expanded="true"`。
- 「コピー」（`permissions: clipboard-read/write`）→ クリップボードがそのブロックの `code` と同じ、ボタンが「コピーしました」、ステータス。
- コピーできないとき（`navigator.clipboard.writeText` を断るようにした場合）→ コードが選択され、ボタンが「Ctrl+C でコピー」、ステータス。
- 閉じ方: 「閉じる」（フォーカスはボタンへ）、Esc、外のクリック、ほかのタブ、PCG の iframe の中のクリック。
- **お手本を実際に動かす**: 本物の P の画面から（または `X1Host.exportPCG` で）ASM タブ（ASM ブロックのあとにカーソル）に $41（青）・$42（赤）を入れ、BASIC タブに BASIC ブロック、RUN → 画面のどこかに文字 65・66 が属性 $20 付きで並び、色が青一色・赤一色。SLANG も同じ（SLANG ブロックのコメントの所に配列を入れて RUN）。
- 1 本目・2 本目の PCG の試験はそのまま通ること。

### Firefox（手で）

- 枠が開く・コピーできる（X1Pen のページに Ctrl+V で貼って同じ）。

### 失敗・後戻り

- 「使い方」は読むだけの枠で、プログラムも保存も変えない（コピーはクリップボードだけ）。後戻りはこの PR を revert。

## Open decisions

1. ボタンの文字は「使い方」（決めごとのとおり。ほかの並びは英語〔Import・Manual・Options・Charmap〕だが、中身が日本語なので日本語にする）。
2. お手本は $41・$42 の 2 文字の形に固定（入れた範囲に合わせて書き換えることはしない。案 B を見送ったのと同じ理由: 番地は X1Pen には分からない）。説明に「1 文字 24 バイト」「文字の数と最初の文字コードに合わせて直す」と書く。

## 実装で変えたこと

- **SLANG のお手本は「先に挿入、その下に貼る」順にした。** お手本の中に `PCG41`（`PCGDEFS($41, PCG41, 2)`）があるので、お手本を先に置いてからそこへ挿入すると、名前がぶつかって配列が `PCG41_2` になる（`slangArrayName` は SLANG のプログラムのどこかにその語があれば番号を付ける）。Chrome の試験で見つかった。→ お手本の 1 行目は配列の名前を含まないコメント（「この上に「X1Pen に挿入」（出力先 SLANG）で入れた配列」）、説明に「先に挿入、その下に貼る。同じ名前がもうあると PCG41_2 などになるので、そのときは PCGDEFS の名前も合わせる」。Node の試験は「挿入した配列 + お手本」をコンパイル、Chrome の試験は新しいプログラムに本物の P の画面から挿入 → その下にお手本を打ち込む → RUN。
- 選択でコピーするとき、Chrome の選択の文字列は最後の改行を含まない（試験はそれに合わせた）。
